# DECISIONS — workbench-tauri v0.1

## D-1. 수치는 `spec/zed-metrics.toml`의 항목 ID로만 참조하고, 원본은 workbench-gpui로 둔다

**선택**

- 크기·간격·색상·폰트·동작 타이밍은 `spec/zed-metrics.toml`의 항목 ID로만 참조한다. 코드에는 ID 이름의 상수나 CSS 변수로 둔다.

**근거**

사용자 결정(2026-11-04). `specs/v0.1/INTENT.md` 범위와 루트 `AGENTS.md` 3장. `spec/`는 616cda5에서 gpui의 것을 그대로 들여왔다.

**배제한 대안**

- **이 레포에서 `spec/`를 직접 고친다** — 두 갈래의 기준이 갈라진다. 사용자가 gpui를 원본으로 정했다(2026-11-04). 배제.
- **01-zed 원문 수치를 코드에 바로 적는다** — 이전 PoC 방식이다. 수치의 기준을 toml 하나로 두기로 했다(2026-11-04). 배제.

## D-2. 프런트엔드 UI 프레임워크는 Solid(`solid-js`)로 한다

**선택**

프런트엔드는 Solid(`solid-js`)로 만든다. 이 선택은 R-01 PoC(프레임워크와 편집기 인스턴스 유지)로 확인한다. PoC가 실패하면 React 19를 대안으로 비교한다.

**근거**

이전 D-3을 그대로 잇는다. leader가 Solid·Svelte 5·React 19를 비교해 Solid를 추천했고, 사용자가 골랐다(2026-11-01). 03-tauri 3.2·3.3은 이 항목을 "미정 (R-01)"으로 두고 세밀한 반응성이 유리하다는 가설을 적었다. 비교에서 든 이유는 다음과 같다.
- 갱신이 signal 단위다.
- 컴포넌트가 실제 DOM 노드를 돌려주므로 미리 만든 `EditorView` 노드를 그대로 끼워 넣기 쉽다(R-01).
- 런타임이 작다(약 7KB).
- workbench-gpui의 Entity + notify 모델과 비슷하다.

위험은 props 구조 분해 같은 반응성 함정이다. `check`의 검토 항목으로 둔다.

**배제한 대안**

- **React 19** — 가상 DOM이 노드를 소유해 `EditorView`를 옮기려면 우회가 필요하고 런타임이 무겁다. R-01 PoC가 실패할 때의 대안으로 남긴다(사용자 결정 2026-11-01).
- **Svelte 5** — rune 문법이 새로워 Svelte 4 문법을 섞어 쓰는 실수가 잦다(사용자 결정 2026-11-01). 배제.

## D-4. 키맵 엔진은 WebView 쪽에 자체 엔진으로 둔다

**선택**

키맵 평가는 WebView 프런트엔드의 자체 엔진이 한다. 평가하는 것은 컨텍스트 깊이 우선, 출처 등급, 연속 키, 메뉴·툴팁에 표시할 키 조회다.

**근거**

이전 D-5를 그대로 잇는다. 사용자가 골랐다(2026-11-01). 03-tauri 2.1은 KeymapEngine을 WebView 쪽에 두고, 3.3은 이 규칙들을 한 곳에서 같은 규칙으로 두려고 자체 엔진을 고른다. R-20과 연결된다.

**배제한 대안**

- **코어(Rust)에서 평가** — 사용자가 WebView 쪽을 골랐다(2026-11-01). 배제.
- **키맵 라이브러리** — 03-tauri 3.3이 같은 규칙을 한 곳에 두려고 자체 엔진을 골랐다(사용자 결정 2026-11-01). 배제.

## D-6. 장식 없는 창은 `decorations: false` + `shadow` + DWM 모서리 속성으로 시작한다

**선택**

창은 `decorations: false`로 만들고 32px 타이틀 바를 직접 그린다. 스냅과 모서리는 `shadow`와 DWM 모서리 속성으로 먼저 맞춘다. 스냅 팝업이 되지 않으면 `windows` 크레이트로 `WM_NCHITTEST`를 처리하는 방식을 더한다.

**근거**

이전 D-7을 잇는다. 사용자가 골랐다(2026-11-01). 03-tauri R-06의 확인 방법과 4절 "타이틀 바·창 장식" 행을 따른다. `windows` 크레이트는 03-tauri 3.1의 후보이므로 루트 `AGENTS.md` 5장의 의존성 범위 안이다. 추가할 때는 9장대로 승인을 받는다.

**배제한 대안**

- **처음부터 `WM_NCHITTEST` 처리를 포함한다** — 사용자가 단계적 방식을 골랐다(2026-11-01). 배제.

## D-7. 창 모서리·테두리는 OS(DWM)에 맡기고, L-311의 앱 그리기는 하지 않는다

**선택**

최대화하지 않은 창의 모서리 둥글림, 테두리, 그림자는 OS(DWM)가 그리게 둔다. 앱은 L-311의 1px 테두리·10px 둥글림·10px 그림자 영역을 그리지 않는다. 이것들은 판정 대상에서 빼고 관찰값만 기록한다.

**배제한 대안**

## D-10. 화면 색 판정은 같은 토큰을 칠한 기준 견본과 대비해 ±1을 주 기준으로 하고, 원본 JSON 직접 대비는 참고값으로 둔다

**선택**

- **주 기준**: 같은 토큰 CSS를 칠한 기준 견본을 앱과 같은 방법(같은 캡처 경로, 같은 창·배율)으로 재고, 앱 픽셀과의 차이가 채널당 ±1 안이면 충족이다. 알파 토큰은 같은 바탕 위에 칠한 견본으로 비교한다.
- **참고값**: 원본 JSON 값(알파 합성 계산)과 앱 픽셀의 직접 차이도 판정표에 적는다. 판정에는 쓰지 않는다.
- 토큰 값 자체(CSS 변수 덤프와 원본 JSON 또는 T-26 규칙의 대조)는 정확히 같아야 한다(A-31.8).

**근거**

이전 D-15를 그대로 잇는다. 원 결정은 leader 위임 결정이다(2026-11-01). 이전 PoC 검증 보고서(태그 `legacy-v0.1-poc`의 `specs/v0.1/verify/phase2/REPORT.md` 10~17행)의 관찰이 근거다. 이 PC에서 WebView2가 칠한 픽셀은 CSS 색과 채널당 1~4쯤 다르고, 앱 밖에서 같은 CSS로 칠한 견본도 똑같이 바뀌었다. 그래서 원본 값과의 직접 대비는 앱이 아니라 화면 색 변환을 재게 된다.

**배제한 대안**

- **원본 JSON 값과의 직접 대비만 쓴다** — 토큰을 그대로 칠해도 단일색 대부분이 ±1을 넘는다(이전 REPORT 10~17행). 배제.

## D-11. 구문 강조는 WebView의 `web-tree-sitter`로 하고, 실패하면 코어를 비교한다

**배제한 대안**

## D-12. Zed 문법 WASM의 `dylink.0` NEEDED는 메모리 사본에서만 건너뛰게 해 로드한다

**선택**

Zed 문법 WASM은 `dylink.0` 섹션의 NEEDED에 `libc.so`가 있어 `web-tree-sitter`가 그대로 로드하지 못한다. 확장에서 읽은 바이트의 메모리 사본에서만 NEEDED 하위 섹션을 로더가 건너뛰도록 바꾼 뒤 로드한다. 디스크의 원본 파일은 바꾸지 않는다.

**근거**

사용자가 이 우회를 받아들였다(2026-11-04). 이전 PoC에서 이 방식으로 HTML 문법이 로드됐다(`specs/v0.1/INTENT.md` 배경).

**배제한 대안**

- **코어의 `tree-sitter` 크레이트로 바꾼다** — D-11의 대안이다. 우회로 WebView 로드가 되므로 쓰지 않는다. 배제.
- **문법을 소스에서 직접 빌드한다** — 외부 도구(`wasi-sdk`)가 필요하다(03-tauri R-13). 배제.

## D-14. CSP를 처음부터 켜고, 확장 파일은 코어의 `zlext` 스킴으로만 주며, CSP에는 그에 필요한 세 항목만 더한다

**선택**

- 첫 빌드부터 CSP를 켠다. 개발자 도구의 위반 보고로 최소 허용 목록을 확인한다.
- 설치된 Zed 확장의 파일(문법 WASM, `.scm`, 아이콘 SVG)은 코어가 커스텀 스킴 `zlext`로 준다. WebView 주소는 `http://zlext.localhost/<확장 id>/<상대 경로>`다.
- 확장 루트는 기본 경로 `%LOCALAPPDATA%\Zed\extensions\installed` 하나다. 루트를 바꾸는 환경변수는 두지 않는다.
- 코어는 요청마다 A-55.2대로 검사한다.
  - 확장 하나의 루트 안 상대 경로만 허용한다.
  - 절대 경로(드라이브, `\\`, 앞의 `/`)와 `..`는 거부한다.
  - 정규화한 실제 경로가 확장 루트 밖이면(밖을 가리키는 링크) 거부한다.
- 경로 검사는 임시 폴더와 정션을 만드는 cargo 단위 테스트 하나로 확인한다. 시험용 명령은 앱에 두지 않는다(D-16).
- 응답의 CORS는 앱 자신의 출처에만 연다.
- CSP(`csp`, `devCsp`)에 더하는 것은 셋이다.
  - `script-src 'self' 'wasm-unsafe-eval'` — WASM 컴파일에 필요하다(R-36).
  - `connect-src`에 `http://zlext.localhost` — 문법 WASM과 `.scm`을 `fetch`로 받는다. 기존 `connect-src` 값은 함께 적는다.
  - `img-src`에 `http://zlext.localhost` — 확장 아이콘 SVG를 `<img>`로 보인다(R-36, R-12).

**근거**

이전 D-10과 D-16을 합쳐 잇는다. D-10은 사용자 결정(2026-11-01), D-16은 leader 위임 지시(2026-11-01)였다. 이전 PoC의 빌드한 앱에서 위 세 항목만으로 CSP 위반이 0건이었다. 03-tauri R-36과 2.4 "보안" 행, 01-zed A-55.2, 루트 `AGENTS.md` 5장. 확장 루트를 기본 경로 하나로 두는 것과 시험용 명령 대신 cargo 단위 테스트로 확인하는 것은 사용자 결정이다(2026-11-04). 코어 파일 이름은 뼈대 작업에서 정한다.

**배제한 대안**

- **CSP를 끄고 시작해 나중에 따로 시험한다** — 사용자가 처음부터 켜는 안을 골랐다(2026-11-01). 배제.
- **에셋 프로토콜(`asset:`)과 Tauri 에셋 범위** — 범위 단위가 폴더 glob이라 A-55.2의 확장 루트별·링크 탈출 검사를 코어가 직접 하기 어렵다. 배제.
- **바이트 응답 명령(`invoke`)** — SVG를 `<img>`로 보이려면 URL이 필요하다. 배제.
- **`'unsafe-eval'`** — WASM 컴파일에는 `'wasm-unsafe-eval'`로 충분하다. 배제.
- **환경변수 `ZEDLIKE_EXT_ROOTS`로 루트를 여럿 지정한다** — 이전 PoC 방식이다. 사용자가 기본 경로 하나로 정했다(2026-11-04). 배제.
- **디버그 빌드 전용 시험 명령(`dev_ext_add_root`)으로 링크 사례를 시험한다** — 이전 PoC 방식이다. 시험용 코드가 앱에 들어간다. 사용자가 cargo 단위 테스트로 대신하기로 했다(2026-11-04). 배제.
