이 절은 아래 모든 요구의 판정 방법에 공통으로 적용한다.

  - 측정값(px, hex). 01-zed 항목 ID별로 기대 값과 나란히 적는다. WebView 쪽 값은 개발자 도구나 스크립트로 덤프한다(A-30.4).
- 치수 판정의 기준은 소스 값(L-, E-)이다. 기준 화면 이미지로 잰 값은 보조 증거다(A-30.2). 치수 허용 오차는 ±1 논리 px다(A-31.1).

  - 통과 기준 수치가 원문에 없는 측정은 측정값과 관찰을 기록하면 충족이다.

## R-1. Solid에서 Pane 사이로 탭을 옮겨도 편집기 인스턴스가 살아남는다 (03-tauri R-01)

**요구**

D-3(Solid)을 확인한다. Pane 분할이나 탭 이동으로 컴포넌트 트리가 바뀌어도 CM6 `EditorView`가 다시 만들어지지 않아야 한다.

**정해진 결과**

- 두 Pane이 있는 작은 PoC가 있다.
- 탭을 한 Pane에서 다른 Pane으로 옮긴 뒤에도 다음이 지켜진다.
  - `EditorView`의 DOM 노드가 옮기기 전과 같은 객체다(파괴되지 않고 옮겨졌다).
  - 옮기기 전의 스크롤 위치, 선택 영역, 커서 위치가 그대로다(03-tauri R-01 "왜" 열).
- 실패했으면 React 19로 같은 PoC를 한 비교 결과가 있다(D-3).

**판정 방법**

공통 판정 방식의 PoC 결과표를 따른다. 증거는 두 가지다.
- 옮기기 전후 노드가 같은지 비교한 스크립트 출력.
- 옮기기 전후의 스크롤·선택·커서 값 덤프.

## R-2. CM6로 Zed 편집기 규격을 맞출 수 있는지 측정해 기록한다 (03-tauri R-02)

**요구**

CM6 확장으로 거터, 선택 레이어, 스크롤바를 만들고 Zed 편집기 치수와 픽셀로 비교한다.

**정해진 결과**

PoC 결과표에 아래 항목마다 기대 값, 측정값, 통과/실패가 있다. 편집기 글꼴은 15px이다(L-08).

| ID | 기대 값 (원문) |
| --- | --- |
| E-002 | 줄 번호 폭 = max(가장 큰 줄 번호의 자릿수 × 숫자 폭, 4 × `ch_advance`). 1~9999줄은 4자리 폭으로 고정 |
| E-003 | 거터 왼쪽 여백 3 ch (`ch` = 글꼴 "0"의 폭) |
| E-004 | 거터 오른쪽 여백 4 ch |
| E-005 | 거터와 본문 텍스트 사이 간격 = 버퍼 글꼴 descent의 절댓값 |
| E-010 | 줄 높이 = 글꼴 크기 × 1.618 (15px에서 24.27px) |
| E-011 | 현재 줄 강조 `"all"`: 거터를 포함해 편집기 왼쪽 끝부터 오른쪽 끝까지, 높이 1줄, 색 `editor_active_line_background`. 비어 있지 않은 선택이 있는 줄은 강조하지 않는다 |
| E-015 | 선택 영역 색 `players[0].selection`, 모서리 반지름 = 0.15 × 줄 높이 (24.27px에서 3.64px) |
| E-030 | 편집기 스크롤바 두께 15px |

- ch 단위 항목(E-002~E-005)의 px는 실제 글꼴 메트릭으로 계산한 기대 값과 비교한다. 01-LAYOUT 4.12절은 이 px 값을 추정으로 적었다.
- 측정은 시스템 고정폭 글꼴로 한다. 기대 값은 그 글꼴의 메트릭(`ch`, descent)으로 계산한다. 쓴 글꼴 이름은 보고서에 적는다. Lilex(`.ZedMono`)는 v0.1에 넣지 않는다(사용자가 골랐다, 2026-11-01, 질문 Q7 A).

**판정 방법**

공통 판정 방식을 따른다. 편집기 탭 스크린샷과 항목별 측정값(px, hex)을 위 ID와 대조한다. 허용 오차는 ±1 논리 px다(A-31.1). 기준 화면 두 장은 미리보기 탭이라 편집기 화면 대조는 하지 않는다(01-LAYOUT "화면 근거 없음").

## R-4. 타이틀 바와 창 버튼이 Zed 치수·모양·색과 같다

**요구**

타이틀 바 높이와 창 버튼의 크기·글리프·색이 Zed 명세와 같다.

**정해진 결과**

- 타이틀 바 높이가 32 논리 px다(L-21, A-32.1).
- 창 버튼은 최소화·최대화(또는 복원)·닫기 순서로 오른쪽 끝에 있다. 각 36×32이고 글리프는 10px다(L-39, L-83, A-32.2).
- 글리프 글꼴은 Windows 11에서 `Segoe Fluent Icons`다. 코드포인트는 최소화 U+E921, 최대화 U+E922, 복원 U+E923, 닫기 U+E8BB다(L-83).
- 최대화하지 않으면 가운데 버튼이 최대화 □(U+E922)이고, 최대화하면 복원(U+E923)이다(L-312).
- 닫기 버튼 hover 배경은 `#E81120`이고 글자는 흰색이다. 누름은 80% 불투명이다. 나머지 버튼의 hover는 `ghost_element_hover`, 누름은 `ghost_element_active`, 글자는 `text`다(L-84).
- 창 버튼은 `minimize`·`toggleMaximize`·`close`에 연결되어 있다(03-tauri 4절).

**판정 방법**

공통 판정 방식을 따른다. 최대화한 상태와 최대화하지 않은 상태의 스크린샷을 남긴다. 치수 측정값(px)과 hover·누름 색 측정값(hex)을 L-21·L-39·L-83·L-84·L-312 ID별로 대조한다. 글리프는 두 가지로 확인한다.
- 코드 근거: 글꼴 이름과 네 코드포인트가 쓰인 위치(파일·줄)를 보고서에 적는다.
- 렌더 확인: 스크린샷의 글리프를 같은 글꼴·코드포인트로 그린 기준 글리프와 나란히 놓고 비교한다.

## R-5. 창 모서리·테두리를 관찰해 기록한다

**요구**

최대화하지 않은 창과 최대화한 창의 모서리·테두리를 확인한다.

**정해진 결과**

- 01-zed에 서로 다른 두 기준이 있다.
  - L-311: 최대화하지 않은 창은 맞닿지 않은 변마다 1px `border` 테두리가 있고, 모서리를 10px 둥글리며, 창 바깥에 10px 그림자 영역이 있다. 최대화하면 둥글림과 테두리가 없다.
  - A-30.6과 T-08.19·T-08.20: 앱이 그리지 않는 창 테두리·모서리는 판정 대상이 아니다(OS 몫).

## R-6. 브라우저 단축키가 자체 키맵 엔진에 도달한다 (03-tauri R-20)

**요구**

WebView2가 먼저 처리하는 단축키를 막고, 그 키가 자체 키맵 엔진(D-5)에 도달하게 한다. 막는 방식은 D-6의 순서를 따른다.

**정해진 결과**

- `AreBrowserAcceleratorKeysEnabled`를 Tauri·wry가 노출하는지와, 그 결과로 고른 방식이 PoC 결과표에 적혀 있다(D-6).
- "확실한 키"가 모두 브라우저 동작(인쇄·찾기·새로고침·뒤로/앞으로·확대)을 일으키지 않고 키맵 엔진에 도달한다.
  - `Ctrl+P`, `Ctrl+F`, `Ctrl+R`, `F5`, `F3`, `Alt+Left`, `Alt+Right`, `Ctrl+Plus`, `Ctrl+Minus` (03-tauri R-20)
- "시험할 키"도 모두 키맵 엔진에 도달한다. 키마다 가로챘는지와 도달했는지가 기록되어 있다. 하나라도 도달하지 않으면 실패다(03-tauri R-20 확인 방법 "위 키 전부", 사용자가 골랐다, 2026-11-01, SPEC 질문 Q5 A).
  - `Ctrl+W`, `Ctrl+Tab`, `F1`, `F6` (03-tauri R-20)
- 브라우저 기본 우클릭 메뉴가 나오지 않는다(03-tauri 4절 "메뉴" 행, 6절 첫 행).

## R-7. 키맵 엔진이 Zed의 충돌·해제·연속 키 규칙대로 평가한다

**요구**

자체 키맵 엔진(D-5)이 Zed의 키맵 규칙을 따른다.

**정해진 결과**

엔진이 다음 규칙을 따르고, 규칙마다 자동 테스트가 있으며 통과한다.
- I-702 충돌: 일치한 포커스 컨텍스트가 더 깊은 쪽이 이긴다. 깊이가 같으면 나중에 등록된 바인딩이 이긴다. 컨텍스트가 없는 바인딩은 가장 깊은 것으로 본다. 조건식이 길다고 우선하지 않는다.
- I-703 해제(`null`): 그 컨텍스트에서 낮은 우선순위 후보를 해제한다. 출처 등급은 사용자 > 기본 덧씌움(VSCode) > Zed 기본이다. 덧씌움의 `null`은 사용자 설정을 지우지 않는다. 이 등급은 깊이·순서 규칙과 섞지 않는다.
- I-001 연속 키: 공백으로 나뉜 조합은 순서대로 누르는 chord다. `Ctrl+K V`는 Ctrl+K를 누른 뒤 V를 따로 누른다.
- I-704 표시 키 조회: 액션 인수까지 같은 바인딩 중에서 고르고, 현재 컨텍스트에서 다른 액션에 가려진 키는 뺀다. 남은 후보 중 마지막 바인딩을 쓴다.

v0.1은 규칙 엔진과 테스트 바인딩까지만 만든다. Zed 키맵 파일(`default-windows.json`, `linux/vscode.json`, `specific-overrides.json`)을 I-700 순서대로 읽어 적용하는 것은 v0.1에서 하지 않는다(사용자가 골랐다, 2026-11-01, SPEC 질문 Q6 A).

**판정 방법**

규칙마다 테스트 이름과 실행 결과(통과 수/전체 수)를 보고서에 적는다. 테스트 입력은 I-702·I-703·I-001·I-704의 문장을 하나씩 사례로 옮긴 것이다.

**출처**
