## R-5. Project Search를 파일명·폴더명으로 위치를 찾는 "Search"로 바꾼다

**요구**

상태 바 돋보기 버튼, `Ctrl-Shift-F`, Project Search 탭을 열린 폴더 안의 파일·폴더 이름 검색으로 바꾼다. 여러 파일의 내용을 찾는 검색과 Replace는 없앤다(지금 `src/search/`, `src-tauri/src/project_search.rs`, `src/search/replace.ts`).

**정해진 결과**

- 이름이 "Search"다. 상태 바 돋보기 버튼의 툴팁과 화면 제목이 "Search"이고, 화면은 지금처럼 탭으로 연다.
- 단축키는 지금처럼 `Ctrl-Shift-F`다.
- 이름 맞추기는 부분 일치다. 검색어가 이름에 들어 있으면 맞는다.
- 결과에서 파일을 누르면 열리고, 폴더를 누르면 트리에서 그 위치가 보인다.
- 대소문자 구분 여부: tauri가 지금 검색 옵션(대소문자 버튼)을 남길지와 함께 보고한다(core ITEMS I-5).
- 단축키 정리(사용자 2026-11-09): Sidebar 폴더 검색은 `Ctrl+F`(R-19), 트리의 파일·폴더 Search는 `Ctrl-Shift-F`(이 요구), 편집 영역 안 `Ctrl+F`는 문서 안 찾기(R-17)다.

**판정 방법**

- 상태 바 돋보기 버튼의 툴팁이 "Search"이고, 누르거나 `Ctrl-Shift-F`를 쓰면 "Search" 탭이 열린다(V3).
- 검색어 `read`를 넣으면 이름에 `read`가 들어간 파일·폴더만 나오고, `rdm`처럼 띄엄띄엄 친 글자로는 `README.md`가 나오지 않는다(V1 테스트, V3).
- 결과에서 파일을 누르면 그 파일이 열리고, 폴더를 누르면 트리에서 그 폴더가 보이게 펼쳐지고 선택된다(V3).
- 파일 내용을 찾는 검색과 Replace가 화면·키맵·코드에 남지 않는다(V1).

## R-8. 모든 스크롤바를 테마 색으로, 더 가늘게, 한꺼번에 같게 한다

**요구**

**정해진 결과**

- 다크 계열 테마에서 스크롤바가 테마 색을 따른다. 밝은 회색·흰색 스크롤바가 보이지 않는다.
- 스크롤바가 지금보다 가늘다. 화살표가 없다.
- 모든 영역의 스크롤바가 같은 모양·색·두께다.
- 지금 스크롤바를 다루는 곳: `src/app.css`, `src/editor/extensions.ts`, `src/shell/picker.css`, `src/theme/theme.ts`(core ITEMS I-8, 파일 검색만).

**판정 방법**

## R-10. Sidebar 폴더 항목은 끌어서 순서를 바꾸고, 마우스를 올리면 닫기 "x"를 보이며, 오른쪽 클릭 메뉴는 Rename 하나만 둔다

**요구**

Sidebar(폴더 목록 패널, v0.5 I-21) 폴더 항목의 오른쪽 클릭 메뉴(지금 Move Up·Move Down·구분선·Remove, `src/shell/Sidebar.tsx` `menuFor`)를 "Rename" 하나로 바꾼다. 순서는 끌어서 바꾸고, 빼기는 "x"로 한다.

**정해진 결과**

- 오른쪽 클릭 메뉴에는 "Rename" 하나만 있다. Zed의 "Rename Title"과 같은 자리·모양이고 글자만 "Rename"이다.
- Rename은 Sidebar에 보이는 이름만 바꾼다. 디스크 폴더 이름은 그대로다. 바꾼 이름은 앱을 다시 열어도 유지한다.
- 항목에 마우스를 올리면 오른쪽 끝에 닫기 "x"가 보인다. 누르면 그 폴더가 목록에서 빠진다(지금 Remove와 같은 동작).
- 항목을 마우스 왼쪽 버튼으로 잡고 위·아래로 끌어 놓으면 순서가 바뀐다.

**판정 방법**

- 항목을 오른쪽 클릭하면 "Rename" 하나만 있다(V3 캡처, Zed 캡처와 자리·모양 비교).
- Rename으로 이름을 바꾸면 Sidebar에 바꾼 이름이 보이고, 디스크의 폴더 이름은 그대로다(탐색기에서 확인). 앱을 다시 열어도 바꾼 이름이 보인다.
- 마우스를 올린 항목에만 "x"가 보이고, 누르면 그 폴더가 목록에서 빠진다. 디스크의 폴더는 그대로다.
- 셋 이상의 폴더에서 맨 아래 항목을 맨 위로 끌어 놓으면 순서가 바뀌고, 앱을 다시 열어도 바뀐 순서가 남는다.

**출처**

I-10(G-5), 사용자 2026-11-09.

## R-12. 탭 바의 Go Back·Go Forward는 문서 안이 아니라 탭 사이를 오간다

**요구**

탭 바 왼쪽의 뒤로(←)·앞으로(→) 버튼과 `Alt+Left`·`Alt+Right`는 탭 사이 선택만 바꾼다. v0.5 I-10에서 탐색 기록에 넣은 문서 안 위치는 기록에서 뺀다. 이 PC Zed에서 탐색 기록이 실제로 어떻게 되는지는 tauri가 확인해 보고에 적는다.

**정해진 결과**

## R-17. 열린 문서 안에서 찾기·바꾸기·선택을 VS Code와 비슷한 기능과 단축키로 한다

**요구**

편집 영역(마크다운·코드·그 밖의 텍스트 파일)에서 찾기, 바꾸기, 여러 곳 선택을 아래 단축키로 쓰게 한다. 기준은 workbench-kit(VS Code 편집기 Monaco 0.56.0, VS Code 기본 단축키)이고 workbench-kit 레포는 읽기만 한다. 찾기·바꾸기 창은 편집 영역 오른쪽 위에 뜨는 작은 창이다. 이미 다른 동작에 쓰던 단축키와 겹치면 편집 영역에서는 VS Code 쪽을 따르고, 밀려난 동작은 보고한다(core D-7). 지금 의존성에 `@codemirror/search`가 없고 키맵(`src/keymap/builtin.ts`)에 해당 단축키가 없다(core ITEMS I-17 확인한 사실).

| 기능 | 단축키 |
|---|---|
| 찾기 창 열기 | `Ctrl+F` |
| 바꾸기 창 열기 | `Ctrl+H` |
| 다음·이전 찾기 | `F3` / `Shift+F3` (찾기 창 안에서 `Enter` / `Shift+Enter`) |
| 대소문자 구분·단어 단위·정규식 켜고 끄기 | `Alt+C` / `Alt+W` / `Alt+R` |
| 하나 바꾸기·모두 바꾸기 | 바꾸기 창 안에서 `Enter` / `Ctrl+Alt+Enter` |
| 찾은 것 모두 선택 | 찾기 창 안에서 `Alt+Enter` |
| 모두 선택 | `Ctrl+A` |
| 선택한 낱말의 다음 일치를 선택에 더하기 | `Ctrl+D` |
| 선택한 낱말의 모든 일치를 선택 | `Ctrl+Shift+L` |
| 마지막에 더한 일치 건너뛰기 | `Ctrl+K Ctrl+D` |
| 줄 선택 | `Ctrl+L` |
| 커서 더하기 | `Alt+클릭`, `Ctrl+Alt+↑` / `Ctrl+Alt+↓` |
| 선택 해제(커서 하나로) | `Esc` |

**정해진 결과**

- 표의 기능이 편집 영역에서 위 단축키로 동작한다.
- `≡` 메뉴의 Edit 메뉴(지금 Undo·Redo 둘, `src/shell/app-menus.ts`)가 workbench-kit의 Edit 메뉴(`workbench-kit/src/core/menu.ts` `DEFAULT_EDIT_ITEMS`)와 같다.
  - Undo `Ctrl+Z`, Redo `Ctrl+Y`
  - (구분선) Cut `Ctrl+X`, Copy `Ctrl+C`, Paste `Ctrl+V`
  - (구분선) Find `Ctrl+F`, Replace `Ctrl+H`
  - (구분선) Toggle Line Comment `Ctrl+/`, Toggle Block Comment `Shift+Alt+A`
  - (구분선) Select All `Ctrl+A`, Add Next Occurrence `Ctrl+D`, Add Cursor Above `Ctrl+Alt+Up`, Add Cursor Below `Ctrl+Alt+Down`
  - 메뉴에 없는 표의 단축키(`Ctrl+Shift+L`, `Ctrl+L` 등)도 편집 영역에서는 동작한다.
- 찾기 아이콘: VS Code codicon `search`(돋보기, workbench-kit `src/core/layout.ts` "Find in Explorer" 버튼). 누르면 찾기 창이 열리고, 열려 있으면 닫힌다. 미리보기(눈) 아이콘이 있는 파일은 그 오른쪽에, 없는 파일(코드 파일 등)은 경로 줄 오른쪽 끝에 둔다. 모든 편집 탭에 있다.

**판정 방법**

## R-18. 상태 바 돋보기 옆 진단 버튼 자리에 마크다운 자동 미리보기 버튼(Lock Preview)을 둔다

**요구**

R-6으로 진단 버튼을 없앤 자리(상태 바 왼쪽, 돋보기 버튼 바로 오른쪽)에 마크다운 아이콘 버튼을 둔다. 켜져 있으면 마크다운 파일을 미리보기 탭으로 연다. 지금 미리보기는 `Ctrl-Shift-V`(`markdown::OpenPreview`), `Ctrl-K V`(`markdown::OpenPreviewToTheSide`), 경로 줄의 눈 아이콘으로 열고, 자동으로 여는 설정은 없다(core ITEMS I-18 확인한 사실).

**정해진 결과**

- 상태 바 아이콘 순서는 Sidebar, Left Dock, 돋보기, 마크다운이다.
- 아이콘은 VS Code codicon `markdown`이다. 경로 줄의 미리보기(눈) 아이콘은 그대로 둔다. 툴팁은 "Lock Preview"다.
- 누를 때마다 켜짐·꺼짐이 바뀌고, 켜진 상태가 눈에 보이게 표시된다. 켜짐·꺼짐은 앱을 다시 열어도 유지한다.
- 켜져 있으면 마크다운 파일을 편집 화면 대신 미리보기 탭으로 연다. 대상은 마크다운만이다. 켠 뒤에 여는 파일부터 적용하고, 이미 열린 탭은 바꾸지 않는다.
- 미리보기 탭에서 `Ctrl-Shift-V`를 누르면 같은 파일의 편집 탭을 더 연다.
- 마크다운 편집 탭과 미리보기 탭 사이의 지금 연계(위치 따라가기, 현재 위치 표시)는 그대로 유지한다. 자동으로 연 미리보기 탭과 `Ctrl-Shift-V`로 더 연 편집 탭 사이에서도 같다.
- 다른 형식(예: HTML) 미리보기 버튼은 이번 버전에서 만들지 않는다.

**판정 방법**

- 상태 바 돋보기 오른쪽에 codicon `markdown` 모양 버튼이 있고, 마우스를 올리면 툴팁이 "Lock Preview"다(V3). 누를 때마다 켜짐·꺼짐이 바뀌고, 켜짐 표시는 Left Dock 버튼의 켜짐 표시와 같은 방식이다. 아이콘 라이선스(codicon, CC BY 4.0)가 Licenses 화면에 있다.
- 버튼을 켜고 마크다운 파일을 열면 편집 탭 없이 미리보기 탭만 열린다. 끄고 열면 편집 탭으로 열린다. 마크다운이 아닌 파일은 켜져 있어도 편집 탭으로 열린다(V3).
- 마크다운 편집 탭을 연 채로 버튼을 켜도 그 탭은 편집 탭으로 남는다.
- 미리보기 탭에서 `Ctrl-Shift-V`를 누르면 같은 파일의 편집 탭이 더 열린다.
- 버튼을 켠 채 앱을 다시 열면 켜짐 상태다. 끈 채 다시 열면 꺼짐 상태다.
- 편집 탭과 미리보기 탭을 나란히 둔 채 편집 탭에서 커서·스크롤을 옮기면 미리보기가 그 위치로 따라가고 위치 표시가 v0.5와 같다. 미리보기에서 옮길 때도 v0.5와 같다(V3, 기존 테스트가 그대로 통과 V1).
