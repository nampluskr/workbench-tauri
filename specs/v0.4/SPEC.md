## R-2. 탭에서 파일을 편집할 수 있고, 수정 상태가 Zed 규칙대로 표시된다 (03-tauri R-08, R-10)

**요구**

탭 편집기의 읽기 전용을 풀고(D-3), 수정 상태를 판정해 탭에 표시한다(L-65, I-071).

**정해진 결과**

- 열린 파일 탭에서 글자를 입력·삭제할 수 있다. v0.2 R-26의 "읽기 전용" 결과는 이 요구로 바뀐다.
- 수정 판정: 현재 문서가 저장 기준 텍스트와 다르면 수정이고, undo로 같아지면 깨끗하다(D-3). 리더 결정(사용자 위임 2026-11-06), S-1.
  - Zed와 다른 점: Zed는 저장 뒤 편집이 undo로 모두 되돌려졌을 때만 깨끗하다(Zed `buffer.rs` `has_unsaved_edits`, `text.rs` `has_edits_since`). 지우고 같은 글자를 다시 쳐서 텍스트가 같아지면 Zed는 수정됨, 이 앱은 깨끗이다. 이 한계를 `shortcut:` 주석으로 남기고 V4 사용자 확인 목록에 올린다.
- 수정한 탭에는 제목 뒤가 아닌 수정 점을 그린다. 점 크기는 `tab.indicator_size`, 색은 Accent 토큰이다(L-65, I-071). 깨끗하면 점이 없다.
- 임시 탭을 편집하면 일반 탭으로 바뀐다(I-063).
- 한글 IME로 조합하는 중에 Enter·Escape·방향키가 마지막 글자를 자르거나 겹치지 않는다(03-tauri R-08). 조합 처리는 CM6 기본 동작을 쓴다.
- 큰 파일(v0.2 R-30과 같은 10MB HTML)을 열어 한 글자 입력할 때의 반영 시간을 기록한다(03-tauri R-10). 원문에 통과 기준이 없어 기록하면 충족이다.
- 되돌리기 묶음 간격이 `editor.undo.group_interval`(E-059c), 탭 크기가 `editor.tab_size`(E-055)다. CM6 설정(history의 묶음 간격, `tabSize`)으로 준다. INTENT 범위의 "편집"에 든다(리더 결정(사용자 위임 2026-11-06), S-3).

**판정 방법**

- 검증 수준
  - V1(`node --test`): 수정 판정 함수(입력 → 수정, undo → 깨끗, 저장 → 깨끗, 충돌 중 undo → 충돌 유지).
  - 코드 확인: `editor.undo.group_interval`·`editor.tab_size`를 CM6 설정에 주는 위치. 설정 한 줄이라 테스트를 두지 않는다(루트 `AGENTS.md` 4.4).
  - V3: 실제 입력으로 글자 입력·undo를 하고 탭 DOM(수정 점 유무, 임시 여부)을 덤프한다. 수정 점 크기·색 토큰은 첫 구현이라 V3로 잰다(루트 `AGENTS.md` 3A.3 1번). 한글 입력기로 조합 중 Enter·Escape·방향키를 눌러 문서 텍스트를 덤프한다. 10MB 파일 입력 반영 시간을 기록한다.

## R-3. 같은 탭의 열기·다시 읽기·저장 요청이 겹치면 마지막 요청 결과만 반영된다

## R-4. 저장 명령으로 디스크 파일이 버퍼와 같아지고, 쓰기는 원자적 교체로 한다

**요구**

저장(Ctrl+S, I-005)을 D-4의 원자적 교체로 만든다.

**정해진 결과**

- 수정한 탭에서 저장하면 디스크 파일이 버퍼 내용(D-5 인코딩·줄 끝 적용)과 같아지고 수정 점이 사라진다.
- 수정하지 않은 탭에서 저장하면 디스크에 쓰지 않는다. 파일 바이트와 수정 시각이 그대로다(D-4, gpui H-15).
- 쓰기 순서: 대상과 같은 폴더에 `<파일명>.<uuid>.tmp`를 `create_new`로 만들어 쓴다 → `sync_all` → 대상이 있으면 `ReplaceFileW`, 없으면 `MoveFileExW`(`MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH`)다(D-4).
  - 교체 재시도는 `app.state_replace_retry_delay` 간격으로 `app.state_replace_retry_count`번이다(D-4, v0.2 R-29와 같은 값).
  - 임시 쓰기에 실패하면 임시 파일을 지우고 원본은 그대로다.
  - 교체에 실패하고 원본이 남아 있으면 임시 파일을 지운다.
  - 교체에 실패하고 원본이 없으면 임시 파일을 남기고, 알림 문구에 그 경로가 있다.
- 저장 중에 그 파일의 경로가 앱 안에서 바뀌면 완료 때 탭이 깨끗해지지 않는다(D-4).
- 자기 저장이 낸 감시 이벤트로 충돌·다시 읽기가 생기지 않는다(D-4, D-7).
- 저장이 실패하면 E-083 문구로 알린다(R-6).
- 다른 이름으로 저장(Ctrl+Shift+S)과 새 버퍼(Ctrl+N, I-005)는 넣지 않는다. I-005 가운데 Ctrl+S만이다. gpui v0.4도 저장만 넣었다(gpui PROGRESS P3-1)(리더 결정(사용자 위임 2026-11-06), S-4).

**판정 방법**

- 검증 수준
  - V1(`cargo test`, 임시 폴더): 처음 쓰기와 교체, 임시 쓰기 실패 뒤 임시 파일 없음·원본 그대로, 교체 실패(대상을 잠가 재현) 뒤 원본이 있으면 임시 파일 없음, 원본이 없으면 임시 파일 남음과 오류 문구의 경로.
  - V1(`node --test`): 깨끗한 탭은 저장 명령을 코어로 보내지 않음, 저장 중 경로 변경 뒤 깨끗해지지 않음.
  - 코드 확인: `state.rs`와 파일 저장이 같은 교체 함수를 부르는 위치(D-4).
  - V3: 실제 Ctrl+S로 저장하고 디스크 바이트와 탭 수정 점을 확인한다.

**출처**

## R-5. 열 때의 인코딩·BOM·줄 끝으로 저장하고, CP949로 옮길 수 없는 글자가 있으면 저장하지 않는다 (03-tauri R-38)

**요구**

D-5의 감지·왕복 규칙을 만든다.

**정해진 결과**

- UTF-8(BOM 있음·없음, LF·CRLF), UTF-16 LE, UTF-16 BE, CP949 파일을 열고 편집해 저장하면 인코딩·BOM·줄 끝이 열 때와 같다.
- 감지 순서는 BOM → 올바른 UTF-8 → CP949다. UTF-16은 BOM으로만 가린다(D-5).
- 줄 끝은 가장 많은 것, 같으면 먼저 나온 것, 없으면 LF다. 편집한 혼합 줄 끝 파일은 그 줄 끝 하나로 저장된다(`shortcut:` 주석, D-5).
- CP949로 옮길 수 없는 글자가 있으면 저장하지 않고, 그 글자를 알린다. 디스크 파일은 그대로다. best-fit 변환은 없다.
- 상태 표시줄에 인코딩 표시가 없다(A-05.5).

**판정 방법**
