# 04 · 두 방식 비교와 Zed 일치도 체크리스트

> 이 파일을 읽는 때: gpui-kit 판과 Tauri 판 중 **어느 쪽부터 만들지** 정할 때, 그리고 구현한 뒤 **Zed 와 같은 수준인지 항목별로 채점**할 때.

| 항목 | 내용 |
| --- | --- |
| 기준 버전 | Windows 11, Rust 1.99.1, gpui-kit 0.8.1 / Tauri 2.12.5 (2026-10-31 조사값). Zed 커밋 [14b7b0e](https://github.com/zed-industries/zed/commit/14b7b0ef3764d62a85070c8b5ccea105a2ad3235) |
| 상태 | 비교는 두 출발 문서의 내용에서 뽑았다. **실행·PoC 검증은 하지 않았다.** 체크리스트의 상태 칸은 **비어 있고** 별도 프로젝트가 채운다 |
| 근거 | [02-gpui/README.md](02-gpui/README.md) (G- 항목), [03-tauri/README.md](03-tauri/README.md) (R- 항목), [01-zed/04-APP-SPEC.md](01-zed/04-APP-SPEC.md) 7절(일치도 판정 기준 A-30 ~ A-35) |

## 1. 두 방식 비교

### 1.1 구조와 스택

| 구분 | gpui-kit (02-gpui) | Tauri 2 + 웹 (03-tauri) |
| --- | --- | --- |
| 프로세스 | 단일 Rust 프로세스. 창은 `Window` (G-001) | Rust 코어 1개 + 창마다 WebView2 화면. WebView2는 렌더러를 창마다 두되 브라우저 프로세스 등은 묶어서 공유한다 (공유 단위는 미확인) |
| 화면을 그리는 것 | gpui 요소 트리 + gpui-kit 컴포넌트 (DirectX 11 / DirectWrite) | HTML / CSS / TypeScript (WebView2) |
| 상태 | Rust `Entity<T>` 한 곳 (G-002) | 영속 상태는 코어, 화면·편집 상태는 프런트엔드 메모리. 코어와 화면 사이 IPC 필요 |
| 편집기 | gpui-kit `Editor` (지원 범위 미확인, G-101) | CodeMirror 6 + `web-tree-sitter` (R-02) |
| 키맵 | gpui `actions!` · `KeyBinding` · `key_context` 를 그대로 사용 (G-005) | 자체 엔진을 만든다 (R-20) |
| 구문 강조 | `tree-sitter` 크레이트 + gpui-component 강조기 | `web-tree-sitter` (기본), 코어 `tree-sitter` (대안) |
| 메뉴·툴팁·Picker | gpui-kit 컴포넌트를 손봄 | DOM 으로 직접 그림 |
| 확인창 | `windows` 크레이트 TaskDialog (G-125) | `tauri-plugin-dialog` 또는 `TaskDialogIndirect` (R-15) |
| 언어 | Rust 한 가지 | Rust + TypeScript + 프레임워크(Solid / Svelte / React 미정, R-01) |
| 핵심 의존 | `gpui-kit 0.8.1` (`gpui-pre =0.3.10` 고정, pre-1.0) | `tauri 2.12.5`, WebView2 런타임, `@codemirror/*` 6.x |
| 공통 | `notify`, `trash`, `nucleo`(MPL-2.0), `serde_json`, `windows`, 휴지통·파일 감시·원자적 쓰기 | 같음 (`nucleo-matcher` 0.3.1) |

### 1.2 강점·약점·위험

| 구분 | gpui-kit | Tauri |
| --- | --- | --- |
| 강점 | Zed 와 **같은 엔진 계열**이라 키 컨텍스트·툴팁·메뉴 동작이 같을 가능성이 높다 (G-111, 판단). 브라우저 단축키 가로채기가 없다. 프로세스 하나, 메모리 적음 (판단) | 편집기(CM6)·마크다운·가상 스크롤 같은 **웹 부품이 풍부**하다. CSS 로 치수·색·rem 을 그대로 옮기기 쉽다. 개발자 도구로 요소 치수를 잰다 (A-30.4) |
| 약점 | gpui-kit `Editor` 가 Zed 편집기 수준인지 불확실. 탭 드래그·Pane 분할·찾기 창·키맵 편집 녹화는 직접 만든다 (G-034, G-036, G-043). 문서·예제가 적다 | 키맵·Pane·탭 드래그·메뉴·툴팁을 DOM 으로 **전부 직접** 구현한다. 코어↔화면 IPC 와 상태 이중 관리가 생긴다 (2.4절) |
| 최대 위험 | 한글 IME (G-100, G-132), 편집기 지원 범위 (G-101, G-131), 버전 변경 (G-130) | 브라우저 단축키 가로채기 (R-20), Pane 이동 때 편집기 상태 소실 (R-01), 장식 없는 창 (R-06), 문법 WASM 호환 (R-19) |
| 일치도에 불리한 곳 | 테마 토큰 매핑 (G-106), 마크다운 미리보기 (G-114) | 창 스냅·모서리 (R-06), 1px 선·글꼴 렌더링 (R-07), IME 조합 (R-08) |
| 일치도에 유리한 곳 | 키·메뉴·툴팁 (같은 gpui) | 치수·색·마크다운 (CSS), 테마 JSON → CSS 변수 (R-11) |

## 2. Zed 일치도 체크리스트

사용법:

- 판정은 [04-APP-SPEC 7절](01-zed/04-APP-SPEC.md)의 기준을 쓴다: 항목마다 **통과 / 실패** (A-30.5), 필수 범주가 하나라도 실패하면 그 범주가 실패다 (A-35.1).
- **상태 칸은 비워 둔다.** 구현 프로젝트가 `통과` / `실패` / `판정 불가` 와 날짜를 적는다. 실패하면 원인이 "두 구현 모두의 문제"인지 "한쪽 프레임워크의 한계"인지 함께 적는다 (A-35.2).
- 항목은 영역별 대표만 넣었다. 전체 ID 는 01-zed 각 문서가 정한다. 괄호의 G-·R- 는 해당 영역을 먼저 확인할 출발 문서 항목이다.
- 치수 기준은 소스 값이고 기준 화면 측정은 보조 증거다 (A-30.2).

## 3. 어느 쪽부터

### 3.1 권장 (판단)

| 순위 | 선택 | 이유 |
| --- | --- | --- |
| 1순위 | **gpui-kit** | ① 명세의 원본이 gpui 로 그려진 Zed 이므로 키 컨텍스트·툴팁·메뉴·다중 창 같은 **동작 일치를 엔진이 도와준다** (G-005, G-111). 점수가 걸린 범주 A-31.3, A-31.4, A-31.15, A-31.13 에 유리 ② 단일 프로세스라 코어↔화면 IPC·상태 이중 관리가 없다 ③ 브라우저 단축키·우클릭 메뉴 가로채기 같은 웹 고유 문제가 없다 (R-20 에 해당 없음) ④ 라이선스가 맞다: gpui·gpui-kit 모두 Apache-2.0, Zed GPL 앱 코드는 가져오지 않는다 |
| 2순위 | Tauri 2 + 웹 | 같은 명세를 만족하는지 확인하는 **비교 대상**이다. 편집기·마크다운·CSS 치수에서 더 쉽게 일치할 수 있어 gpui 판의 막힌 곳을 메우는 참고가 된다 |

두 판의 명세 수준은 같다. 순위는 구현 순서의 제안이다 (03-tauri 머리 표와 같은 입장).

### 3.2 Tauri 를 택할 조건 (판단)

gpui 판의 첫 PoC(02-gpui 7절 1 ~ 2단계) 결과가 아래이면 Tauri 를 먼저 한다.

| 조건 | 관련 항목 | Tauri 쪽에서 같이 확인할 것 |
| --- | --- | --- |
| 한글 IME 가 gpui-pre 에서 실사용 불가 (조합 표시·후보창 위치·확정 오류) | G-100, G-132 | R-08 |
| gpui-kit `Editor` 가 거터·선택·다중 커서·스크롤바 일치(A-31.1)를 맞출 수 없고 `Element` 직접 작성 비용이 큼 | G-101, G-131 | R-02 (CM6) |
| 큰 파일(10만 줄)에서 gpui-kit 편집기가 느림 | G-102 | R-10 |
| 탭 드래그·Pane 분할을 gpui-kit `dock` 으로 못 하고 직접 구현 비용이 큼 | G-104, G-135 | R-09, R-01 |
| tree-sitter `wasm` 기능이 gpui-component 강조기와 함께 쓸 수 없고 확장 문법을 못 읽음 | G-108 (A-57.7) | R-03, R-19 |
| 개발자가 웹 기술에 익숙하고 gpui 의 변경·문서 부족을 감당하기 어려움 | G-118, G-130 | — |

반대로 Tauri 의 P0 항목(R-01, R-02, R-03, R-06, R-19, R-20) 중 해결 불가가 나오면 gpui 쪽이 유력해진다.
